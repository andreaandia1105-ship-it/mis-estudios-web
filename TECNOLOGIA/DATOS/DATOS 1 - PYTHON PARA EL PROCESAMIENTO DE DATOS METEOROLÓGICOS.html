🔵 BLOQUE 1 · FUNDAMENTOS DEL LENGUAJE PYTHON
Por qué Python en meteorología (Diap. 1–4)
Python es un lenguaje interpretado, de alto nivel, creado a finales de los años 80 por Guido van Rossum. "Interpretado" significa que no necesitas compilar el código antes de ejecutarlo: el intérprete lee y ejecuta línea por línea, lo cual acelera enormemente el ciclo de prueba-y-error típico del análisis de datos científicos.
Su sintaxis usa indentación obligatoria en vez de llaves {}, lo que fuerza a escribir código legible casi por diseño: dos personas que programan el mismo algoritmo en Python producen bloques visualmente similares.
Su verdadero poder para meteorología no está en el lenguaje puro, sino en su ecosistema científico: NumPy para arreglos numéricos, Pandas para tablas, Xarray para datos con múltiples dimensiones (como salidas de modelos WRF), Matplotlib para graficar y Cartopy para mapas georreferenciados.
Es multiplataforma: el mismo script corre en Windows, Linux o macOS sin modificaciones, lo cual es clave cuando se comparte código entre estaciones de trabajo y servidores de cómputo científico (por ejemplo, un clúster que corre WRF en Linux).

⚠️ ERROR COMÚN: confundir "lenguaje interpretado" con "lenguaje lento por definición". Python en sí es más lento que C, pero NumPy y Pandas ejecutan sus operaciones internamente en C precompilado, por lo que el cuello de botella real casi nunca está en las librerías científicas bien usadas, sino en bucles `for` escritos manualmente sobre datos grandes.

Tipos de datos primitivos (Diap. 6)
Un tipo de dato primitivo es la unidad más básica de información que Python reconoce de forma nativa. Toda variable meteorológica que registres (temperatura, humedad, una bandera de alerta) se apoya en uno de estos cuatro tipos.
Entero (int)
Números sin parte decimal. Ej: HR = 98. Útil para conteos (número de estaciones, día del mes).
Flotante (float)
Números con decimales. Ej: t = 24.6. Es el tipo natural para casi toda variable física continua como temperatura o presión.
Cadena (string)
Texto entre comillas. Ej: estacion = 'Von Humboldt'. Sirve para identificar estaciones, unidades o etiquetas.
Booleano (bool)
Solo True o False. Ej: alerta = True. Es el resultado natural de cualquier comparación lógica (¿la temperatura supera el umbral?).
⚠️ ERROR COMÚN: guardar un valor de humedad relativa "98%" como texto ("98%") en vez de como número (98 o 0.98). Si queda como string, Python no podrá promediarlo, compararlo ni graficarlo sin antes convertirlo explícitamente.

Operadores (Diap. 7)
Los operadores son símbolos que combinan valores para producir un resultado. Se dividen en aritméticos (producen números) y de comparación (producen booleanos).
3.5 // 2 = 1.0 (división entera)
7 % 2 = 1 (módulo/resto)
2 ** 6 = 64 (potencia)
La división entera (//) descarta la parte decimal; el módulo (%) devuelve solo el resto. Juntos permiten, por ejemplo, convertir un total de horas en días y horas sobrantes.
⚠️ ERROR COMÚN: usar / cuando se necesita // para obtener un índice entero (por ejemplo, al calcular a qué "bin" horario pertenece un dato), lo que produce un float que luego falla al indexar una lista.

🟢 BLOQUE 2 · LÓGICA DE PROGRAMACIÓN
Estructuras de control: condicionales (Diap. 8)
Los condicionales permiten que el programa tome decisiones distintas según el estado de los datos, replicando el razonamiento de un meteorólogo que aplica reglas ("si la temperatura supera 30°C, emitir alerta").
if temperatura > 30:
    alerta = 'Ola de calor'
elif temperatura < 10:
    alerta = 'Frío intenso'
else:
    alerta = 'Normal'
Python evalúa las condiciones en orden y ejecuta solo el primer bloque cuya condición sea verdadera; el resto se ignora aunque también fueran técnicamente ciertas.
elif es la contracción de "else if": permite encadenar múltiples condiciones sin anidar bloques `if` uno dentro de otro, lo que mantiene el código legible.
⚠️ ERROR COMÚN: olvidar los dos puntos ":" al final de la línea del if/elif/else, o mezclar indentación con espacios y tabulaciones, lo cual en Python es un error de sintaxis (no solo de estilo).
🎯 EXAMEN: Diseñe una estructura condicional que clasifique la intensidad de precipitación en "llovizna", "moderada" y "fuerte" según umbrales típicos de mm/h usados en boletines de SENAMHI.
Bucles (Diap. 8)
Un bucle repite una acción sobre una secuencia de datos o mientras se cumpla una condición, evitando escribir la misma línea de código decenas o miles de veces.
for dia in temperaturas:
    print(dia)
for recorre una secuencia finita conocida de antemano (una lista de 365 temperaturas diarias).
while se repite mientras una condición sea verdadera, útil cuando no se sabe de antemano cuántas iteraciones harán falta (por ejemplo, leer datos hasta encontrar el fin de archivo).

🩵 BLOQUE 3 · ESTRUCTURAS DE DATOS Y FUNCIONES
Tipos de datos compuestos (Diap. 9)
Un dato compuesto agrupa varios valores primitivos bajo una sola variable. Son la base para representar series meteorológicas completas en vez de un solo valor aislado.
Lista [ ]
Ordenada, mutable (se puede modificar tras crearla), permite duplicados. Ideal para una serie temporal que va creciendo, como temperaturas horarias de un día.
Tupla ( )
Ordenada pero inmutable: una vez creada no cambia. Útil para coordenadas fijas de una estación (latitud, longitud) que no deben alterarse por error.
Diccionario { }
Pares clave-valor, sin orden posicional garantizado antes de Python 3.7. Ideal para asociar cada ciudad con su temperatura: {'Lima': 24, 'Bogotá': 22}.
⚠️ ERROR COMÚN: intentar modificar una tupla con `tupla_1[0] = 5`, lo que lanza un TypeError porque las tuplas son inmutables por diseño (a diferencia de las listas).
🎯 EXAMEN: Si necesita almacenar la temperatura de 10 ciudades peruanas y luego consultar rápidamente el valor de "Arequipa" sin recorrer toda la colección, ¿qué estructura de datos es más eficiente y por qué?
Funciones (Diap. 12)
Una función encapsula un bloque de código que realiza una tarea específica y solo se ejecuta cuando es llamada, evitando repetir lógica y facilitando pruebas aisladas.
def celsius_a_kelvin(temp_c):
    return temp_c + 273.15
El parámetro (temp_c) es una variable local que solo existe dentro de la función; el valor real se le pasa al invocarla, ej. celsius_a_kelvin(24.6).
return entrega el resultado a quien llamó la función; sin él, la función devuelve None aunque internamente calcule algo.

🟣 BLOQUE 4 · NUMPY: CÓMPUTO NUMÉRICO VECTORIZADO
Qué es NumPy y por qué es rápido (Diap. 14–15)
NumPy es el paquete fundamental para computación científica en Python. Su objeto central es el array (arreglo) multidimensional, que almacena datos numéricos homogéneos de forma mucho más compacta y eficiente que una lista de Python.
Un array 1D es una fila de valores (ej. una serie horaria de temperatura); un array 2D es una tabla (ej. temperatura por estación y por día); un array 3D agrega una tercera dimensión, típicamente usada para representar campos meteorológicos con latitud, longitud y tiempo, como en salidas de modelos numéricos.
La vectorización es la ausencia de bucles explícitos: en vez de recorrer cada elemento con un `for`, NumPy aplica la operación a todo el arreglo de una sola vez, delegando el trabajo a código C precompilado "detrás de escena".
Esto no es solo una ganancia estética: para un arreglo de un millón de datos (por ejemplo, salidas horarias de WRF durante varios años), un bucle `for` en Python puro puede tardar órdenes de magnitud más que la misma operación vectorizada en NumPy.
⚠️ ERROR COMÚN: escribir bucles `for` manuales sobre arrays de NumPy en vez de usar operaciones vectorizadas (ej. `array + 273.15` en vez de recorrer elemento por elemento), lo que anula la principal ventaja de rendimiento de la librería.
🎯 EXAMEN: Explique con sus propias palabras por qué se dice que un array de NumPy "consume menos memoria" que una lista de Python equivalente, y qué relación tiene esto con que los datos sean homogéneos (todos del mismo tipo).
Dimensiones de un array
1D → shape (4,)
2D → shape (2, 3)
3D → shape (4, 3, 2)
El "shape" indica cuántos elementos tiene el arreglo en cada dimensión; conocerlo es el primer paso antes de operar sobre cualquier dato meteorológico matricial.

🩷 BLOQUE 5 · PANDAS: DATOS TABULARES Y ETIQUETADOS
Qué es Pandas y su estructura de datos (Diap. 17–20)
Pandas es el paquete fundamental para trabajar con datos "relacionales" o etiquetados: aquellos que naturalmente se organizan en filas y columnas, como una hoja de cálculo o una tabla de estaciones meteorológicas.
Está construido sobre NumPy, por lo que hereda su velocidad, pero añade etiquetas (nombres de columnas, índices de fila) que hacen el código mucho más legible: en vez de referirse a "la columna 3", se referencia como df['temperatura'].
Series es la estructura unidimensional (una sola columna con índice); DataFrame es la estructura bidimensional (varias columnas alineadas por el mismo índice), equivalente conceptual a un data.frame de R o a una hoja de Excel.
Cuando se suman dos Series con el mismo índice, Pandas alinea automáticamente los valores por etiqueta antes de operar, no por posición, lo que evita errores silenciosos al combinar datos de fuentes distintas.
⚠️ ERROR COMÚN: asumir que Pandas alinea los datos por posición (como una lista) en vez de por índice/etiqueta; si dos DataFrames tienen índices distintos, una suma directa puede generar valores NaN inesperados en vez de un error visible.
🎯 EXAMEN: ¿Qué diferencia estructural existe entre una Series y un DataFrame de Pandas, y por qué un registro diario de temperatura, presión y humedad para una sola estación se representa mejor como DataFrame que como Series?
Fortalezas de Pandas para meteorología
Manejo nativo de datos faltantes (NaN), algo constante en series meteorológicas reales con sensores que fallan o se desconectan.
Funcionalidad específica de series temporales: generación de rangos de fechas, remuestreo de frecuencia (ej. de datos horarios a promedios diarios) y estadísticas de ventana móvil.
Lectura directa de CSV, Excel y otros formatos tabulares comunes en boletines y bases de datos hidrometeorológicas.
